# Market Replay — ручное тестирование

Отдельный режим приложения (вкладка «Market Replay» в навигации, не связана с
автоматическим бэктестером) для пошагового ручного тестирования стратегий на
исторических данных в духе TradingView Bar Replay: пользователь видит только
то, что «известно» на выбранный момент времени, шаг за шагом раскрывает
следующие свечи и может торговать вручную (Buy/Sell/Short/Close, стоп-лосс/
тейк-профит, комиссия, проскальзывание) с реальным учётом P&L.

## Архитектура (backend)

- `replay_db.py` — SQLite `storage/replay.db` (WAL, короткоживущие соединения):
  таблица `replay_sessions` (тикер, таймфрейм, момент старта, индекс раскрытых
  баров, баланс, позиция, реализованный P&L, стек отмены) и `replay_trades`
  (каждое исполнение — открытие/добавление/сокращение/закрытие).
- `replay_engine.py` — вся торговая логика и логика воспроизведения:
  `create_session`, `step`/`step_back`, `goto`, `reset`, `place_order`.
- Состояние сессии живёт **целиком в SQLite**, не в памяти Python-процесса —
  gunicorn работает несколькими воркерами, любой запрос может попасть на любой
  из них; перезагрузка страницы или обрыв соединения не теряют прогресс.

## Как исключён показ будущих данных (anti-look-ahead)

Это структурное свойство API, а не фильтр поверх готовых данных:

- Каждая сессия хранит `reveal_index` — сколько баров, начиная с момента
  старта, уже «раскрыто».
- `visible_state()` — единственная функция, отдающая данные фронтенду —
  запрашивает у `market_data_store`:
  - контекст **до** момента старта (`before=start_ts`) — сколько угодно,
    это прошлое, его можно видеть целиком;
  - раскрытые бары **от** момента старта — строго `LIMIT reveal_index`
    (`get_candles_ascending(..., limit=reveal_index)`), т.е. физически
    невозможно получить бар с индексом `reveal_index+1` и дальше.
- Нет отдельного кода, который мог бы «случайно» отдать более свежий бар —
  индикаторы, автомасштаб и подписи шкалы на фронтенде считаются из уже
  урезанного на сервере набора данных, поэтому они **не могут** увидеть
  будущее, даже если бы захотели.
- Стоп-лосс/тейк-профит проверяются **только** по диапазону (high/low) только
  что раскрытого бара (`_check_stop_take`), не заглядывая вперёд.
- `goto()` (прыжок на дату) проходит по всем барам прыжка **по порядку** и
  проверяет стоп/тейк на каждом — уровень, пробитый на пути, не проскакивается
  молча.

## Управление

| Действие | Клавиша/кнопка |
|---|---|
| Пуск/пауза | Пробел (не срабатывает, если фокус в поле ввода/textarea/select) |
| Один шаг вперёд | → или кнопка «Вперёд» |
| Один шаг назад | ← или кнопка «Назад» |
| Перезапуск сессии | Кнопка «Перезапустить» (сброс к началу, баланс/позиция/сделки очищаются) |
| Переход к дате | Кнопка «Перейти к дате…» → дата/час/минута |
| Скорость | Селектор 1×/2×/5×/10×/25×/50×/Максимум (клиентский таймер, дергает `/step` с интервалом `700мс / скорость`) |

Пробел не скроллит страницу (`preventDefault`) и не перехватывает ввод в полях
формы (ручная сделка, дата перехода) — проверено автотестами и вживую.

## Шаг назад (undo)

Каждое изменяющее состояние действие (шаг вперёд, ручная сделка) перед
выполнением кладёт снимок состояния в ограниченный стек (до 200 записей) плюс
«водяной знак» — id последней записанной сделки на тот момент. Шаг назад:

1. Восстанавливает снимок (баланс, позиция, `reveal_index`).
2. Удаляет из БД все сделки с `id` больше водяного знака — иначе повторный шаг
   вперёд задвоил бы сделку вместо того, чтобы создать её заново.

Так один шаг назад безопасно отменяет ровно одно действие, даже если на одном
баре было сделано несколько сделок.

## Ручная торговля

- **Buy** — открыть/увеличить длинную позицию (запрещено, если открыт шорт —
  сначала Close).
- **Short** — открыть/увеличить короткую (запрещено при открытом лонге).
- **Sell** — сократить/закрыть длинную позицию.
- **Close** — закрыть текущую позицию целиком (лонг или шорт).
- Цена исполнения — цена закрытия последнего раскрытого бара с
  проскальзыванием (`slippage_bps`, в базисных пунктах, хуже для трейдера в
  сторону движения — покупка дороже, продажа дешевле).
- Комиссия — `commission_rate` (доля от нотионала), взимается на каждом
  исполнении (вход и выход).
- **Реализованный P&L** по закрывающей сделке честно включает
  пропорционально распределённую комиссию входа (не только комиссию выхода) —
  иначе цифра P&L была бы красивее реальности.
- Лимит размера лота берётся из справочника MOEX (`LOTSIZE`) для тикера сессии.
- Недостаточный баланс — сделка отклоняется с понятной ошибкой, средства не
  уходят в минус.

## Сохранение и восстановление сессии

Все сессии видны в списке «Незавершённые сессии» на экране настройки (`GET
/api/replay/sessions`). Активная сессия дополнительно запоминается в
`localStorage` браузера — при перезагрузке страницы плеер открывается сразу на
той же сессии и том же баре, без необходимости искать её в списке.

## Ограничения

- **Тики недоступны** — MOEX ISS не отдаёт исторический тиковый архив через
  эту интеграцию. Replay всегда работает по свечам, минимальный доступный
  таймфрейм — 1 минута (см. `docs/HISTORICAL_DATA.md` → «Тиковые данные»).
  Это указано прямо в форме запуска сессии.
- Позиция моделируется упрощённо (одна нетто-позиция на сессию: лонг ИЛИ
  шорт, не обе одновременно) — прямой разворот в одной заявке не
  поддерживается, сначала нужно закрыть текущую позицию.
- Маркировка на графике при частичном сокращении позиции визуализирует вход и
  первый выход как одну «сделку»; последующие частичные сокращения того же
  входа рисуются как отдельные выходы от той же точки входа — приемлемое
  упрощение для отображения, экономика (P&L, комиссия) при этом считается
  точно на бэкенде.
- Клиентский буфер свечей на графике не обрезается на очень длинных сессиях —
  при пошаговом проходе через многие тысячи баров массив свечей в браузере
  продолжает расти (сервер же, наоборот, всегда отдаёт только то, что нужно —
  утечки на бэкенде нет). Для типичной длины сессии (часы-дни торгов на
  минутном/10-минутном таймфрейме) это не проблема; известное ограничение для
  экстремально длинных сессий.

## Как запустить

1. Вкладка «Market Replay» → выбрать тикер, площадку, таймфрейм, дату/час/
   минуту старта, начальный баланс, комиссию, проскальзывание, скорость.
2. «Запустить воспроизведение» — сервер поднимает историю **до** момента
   старта как контекст (график сразу что-то показывает), сам момент старта
   ещё не раскрыт.
3. Шаг вперёд (→ или пробел) раскрывает бары один за другим; при активной
   позиции на каждом баре автоматически проверяются стоп/тейк.
4. Ручная сделка — панель справа (лоты, Stop Loss, Take Profit, Buy/Sell/
   Short/Close).
5. «Удалить сессию» — безвозвратно удаляет сессию и все её сделки.
