# TradingView parity — итоговый отчёт (сессия 2026-08-18)

Полное ТЗ на этот раунд требовало довести chart workspace Strategy Lab до
уровня TradingView Supercharts по 178 пунктам — это описание
многомесячного проекта, а не одной сессии. Проект уже прошёл несколько
предыдущих раундов именно этой работы сегодня (см. `git log`: `d7f7227`
«bring "Анализ графиков" to TradingView parity», затем пять
`charts-mobile`-коммитов, приводивших верхний/нижний ряд тулбара к
референсу пиксель-в-пиксель). Эта сессия — не старт с нуля, а ревизия
существующей реализации: полный аудит (`docs/tradingview-chart-audit.md`),
построение честной parity-матрицы (`docs/tradingview-parity-matrix.md`) и
исправление того, что аудит реально нашёл сломанным, вместо повторной
реализации того, что уже работает.

## Что было найдено и исправлено

### 1. Мёртвая кнопка «Д» (BUG 1 из ТЗ) — root cause найден и исправлен

Кнопка была не заглушкой «пока не реализовано» — она была намеренно
сделана неинтерактивной (`aria-hidden`, `tabindex="-1"`,
`pointer-events:none`) предыдущим раундом, который не смог опознать её
смысл по референс-скриншоту и, что хуже, следующим коммитом спрятал уже
работавший переключатель таймфрейма, посчитав его дублирующим.

На самом деле «Д» — это и есть TradingView-переключатель таймфрейма,
показывающий текущий интервал в сокращении (Daily → «Д» на
ru.tradingview.com). Исправлено: единый рабочий контрол
`#slTvIntervalBtn`, показывающий интервал в правильном сокращении
(число для минут, «Nч» для часов, Д/Н/М для дня/недели/месяца), тап
открывает попап всех 12 поддерживаемых интервалов через уже
существующую систему попапов (`_wireGlobalPopover`, phone bottom-sheet
CSS). Дублирующая «заплатка» — группа «Таймфрейм» внутри «...»-меню,
добавленная предыдущим раундом как обходной путь — удалена.

**Верифицировано вживую** на `strategylab.generationweb.ru` (390×844):
тап → попап → выбор «1ч» → график и пилюля переключились синхронно,
`#gtTimeframe.value` (source of truth) синхронен, консоль чистая.

### 2. Magnet — Weak/Strong вместо boolean

ТЗ (§72) требует три режима: Off / Weak (снап только когда курсор уже
близко к значению) / Strong (снап всегда). Было — один boolean
(`snapEnabled`), фактически всегда работавший как Strong. Исправлено:
`DrawingManager.magnetMode` (`"off"|"weak"|"strong"`), Weak проверяет
пиксельное расстояние между сырой и притянутой ценой
(`priceToCoordinateSafe`), не price-расстояние — так поведение не
зависит от масштаба/зума, как в реальном TradingView. Кнопка на рейле и
пункт в десктопном «...»-меню оба переключают по кругу и показывают,
какой режим активен (буква W/S на рейле, текст в меню).

**Верифицировано** напрямую против реальных данных активной свечи на
проде: Strong снапает точку, отстоящую от любого OHLC-значения на 5×
диапазон свечи; Weak ту же точку не трогает, но снапает точку в ~14px от
значения; Off не снапает никогда.

## Что аудит подтвердил уже работающим (не переделывалось)

Значительная часть P0/P1 из ТЗ уже реализована предыдущими раундами и
подтверждена этим аудитом как минимум на уровне кода, местами — вживую:

- **Drawing engine**: единый Pointer Events state machine (не raw DOM per
  tool), координаты `{time,price}` (никогда пиксели), 20 типов
  инструментов, undo/redo с одной записью на operation (не на
  pointermove), персистентность per-symbol через `/api/chart-drawings`.
- **Object Tree** («Объекты»): select/hide/lock/rename/delete с
  двусторонней синхронизацией canvas ↔ список.
- **Alerts**: реальный серверный `/api/alerts` (не только пока открыта
  страница) + polling `/api/alerts/events`, тап по шкале цены и
  context-menu «Добавить алерт здесь» открывают форму с точной ценой.
- **Fullscreen**: настоящий Fullscreen API с CSS-фолбэком, Escape работает
  в обоих случаях.
- **Мультиграфики**: 7 раскладок, синхронизация ticker/interval/
  crosshair/scroll/zoom/range с защитой от echo-эффекта.
- **Context menu**: right-click/long-press на объекте и на пустом холсте,
  разные пункты меню.
- **Per-tool style defaults**, **visibility by timeframe**, **Long/Short
  Position с редактируемыми handles** — всё уже реализовано.

## Что осталось MISSING/PARTIAL (честно, из parity-матрицы)

Полный список — `docs/tradingview-parity-matrix.md`. Главное:

- **Визуальный «+» на price scale** (следует за курсором) отсутствует —
  есть только функциональный эквивалент (тап по шкале → алерт), без
  самой иконки и без пункта «Add Horizontal Line» в этом меню.
- **Продвинутые инструменты рисования**: Gann-семейство, Pitchfork-семейство,
  паттерны (XABCD/Elliott Wave/Head&Shoulders/...), большая часть
  Fibonacci-семейства кроме Retracement/Extension, Anchored VWAP/Volume
  Profile, Multiselect, Grouping — не реализованы (P2/P3 по ТЗ).
- **Measure tool** в TradingView-смысле (временный оверлей с
  ценой/%/барами/временем без создания персистентного объекта) — вместо
  него есть три персистентных drawing-инструмента с той же математикой
  (Price Range/Time Range/Price&Time Range).
- **Floating toolbar** при выборе объекта — реализовано как нижняя панель
  «Свойства», не как плавающий toolbar рядом с объектом.
- **Alert line на графике** — не подтверждено, что активный алерт рисуется
  как horizontal line с меткой прямо на холсте; требует отдельной проверки.
- **Reference pack** (§4 ТЗ, 25 состояний × 4 mobile viewport) не собирался
  — не было доступа к живому TradingView для скриншотинга, только
  предоставленные `Tradingview.PNG`/`Strategy Lab.png`.
- **Real iOS Safari** не тестировался — вся touch-верификация через
  Chromium Pointer Events эмуляцию.
