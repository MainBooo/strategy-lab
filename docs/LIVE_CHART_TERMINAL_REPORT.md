# «Анализ графиков» как живой рыночный терминал — отчёт

Дата: 2026-08-05. Изменения выполнены и проверены Playwright'ом во время открытой торговой сессии MOEX (14:49–15:02 МСК). Ничего не закоммичено в git (как и вся предыдущая незакоммиченная работа в репозитории) — по запросу пользователя.

## Что уже было готово ДО этой сессии (другая сессия, тот же день)

Значительная часть требований технического задания уже была реализована и вживую проверена ранее:

- Историческая свечная лента через `/api/candles`, backend'ом — ограниченный SQLite-кэш с TTL/LRU-вытеснением (`market_data_store.py`).
- Ленивая подгрузка истории влево (`ChartCore._maybeLoadOlder`/`_fetchOlderPage`) без сброса позиции экрана.
- Инкрементальное обновление последней свечи через `series.update()`, а не `setData()` (`ChartCore.appendCandle`) — включая объём.
- Честный индикатор задержки (`static/realtime-indicator.js` + `market_ticker.get_realtime`), который никогда не показывает «live», только измеренную задержку MOEX ISS (~15 мин).
- Изоляция Market Replay от live-подписки (`RealtimeIndicator.showReplayMode()`), корректная остановка polling при уходе со вкладки/тикера (visibilitychange, `onTabLeave`).
- Разметка (линии/зоны/тексты/позиции), привязанная к тикеру/таймфрейму, с автосохранением на бэкенд (`/api/chart-layouts`, `/api/chart-drawings`).
- Fullscreen, индикаторы, синхронизация нескольких плиток.

## Что было доделано в этой сессии (закрывает разрыв с новым ТЗ)

1. **Аудит источника данных** — `docs/LIVE_MARKET_DATA_SOURCE_AUDIT.md`. Подтверждено фактически (grep по репозиторию, `.env`, systemd unit): используется исключительно бесплатный анонимный MOEX ISS, без ALGOPACK/токенов/авторизации. Измеренная задержка ~15 мин уже была честно отражена в UI — задача была подтвердить, а не создавать заново.

2. **Режим «следования за рынком» + кнопка «К последней цене»** (`static/chart-engine/core.js`, `chart-tile.js`, `chart.css`) — этого не было. Теперь: `ChartCore` отслеживает, находится ли правый край видимого диапазона у последней свечи (`_updateFollowState`, подписка на `subscribeVisibleLogicalRangeChange`, которая уже использовалась для ленивой подгрузки истории). Пока пользователь не у края — новые бары не двигают экран (естественное поведение `series.update()` в lightweight-charts), только копится счётчик; кнопка «К последней цене · +N» появляется поверх графика и по клику (`scrollToRealTime()`) возвращает на живой край. Проверено в Playwright: скролл влево → появление кнопки → 3 синтетические live-свечи → счётчик +3, экран не сдвинулся → клик → возврат, счётчик сброшен.

3. **Живое тиканье дневной свечи во время сессии** (`static/chart-analysis.js`) — раньше 1д/1н/1мес были намеренно исключены из live-тика. Так как сутки — фиксированные 86400 секунд (МСК без перехода на летнее время), дневной таймфрейм добавлен в `LIVE_TICK_BUCKET_SECONDS` тем же механизмом, что и внутридневные бары. 1н/1мес по-прежнему не тикают (торговая неделя/месяц — не фиксированное число дней из-за праздников), это отдельная и осознанная граница, а не недоработка.

4. **Переключение типа графика: свечи / бары / линия / область** (`core.js`, `chart-analysis.js`, `chart-tile.js`, `chart.css`) — раньше вообще не было. lightweight-charts v5.2.0 (подтверждена версия и наличие `CandlestickSeries/BarSeries/LineSeries/AreaSeries/removeSeries/scrollToRealTime` в бандле перед использованием) не поддерживает смену типа серии на месте — сделано удаление старой серии и создание новой с переносом данных. Самый рискованный момент — разметка (`DrawingManager`) кэширует ссылку на серию для `attachPrimitive`/`priceToCoordinate`; добавлен `DrawingManager.rebindSeries()` и событие `ChartCore.onSeriesChange`, чтобы слой разметки переподключался к новой серии без потери объектов. Проверено визуально в Playwright: переключение свечи→линия→область с уже нарисованными линией тренда и зоной — разметка осталась на месте, ошибок в консоли не появилось. Тип графика сохраняется в `chart_layouts.chart_type` (поле в БД уже существовало) и в workspace localStorage — переживает сохранение шаблона и перезагрузку страницы.

5. **Bid/Ask в попапе индикатора** (`static/realtime-indicator.js`) — бэкенд их уже отдавал (`market_ticker.get_realtime`), фронтенд не показывал. Добавлены строки Bid/Ask, скрываются при `null` (неликвидный инструмент/книга пуста), не показывают «н/д» без нужды.

## Не проверено вживую (честно)

- Полный сценарий возврата на вкладку из фонового таба (`visibilitychange`) с реальным networked-разрывом — код не менялся в этой части, полагаюсь на предыдущую сессию, которая заявляла это проверенным.
- Реальный сценарий обрыва MOEX ISS и автопереподключения (нужно реально уронить сеть/эндпоинт).
- Полный прогон Market Replay «запустить воспроизведение → шаг → live-индикатор не появляется» — дошёл только до экрана настройки (индикатор ещё не создан на этом экране, что ожидаемо), не кликал «Запустить» до конца, чтобы не плодить тестовые сессии в БД реплея.
- Мультиграфики (2/4/6 плиток) с несколькими live-подписками одновременно — по архитектуре live тикает только активная плитка (осознанное ограничение из docstring `chart-analysis.js`), не тестировал отдельно в этой сессии.
- Недельный/месячный таймфрейм намеренно не тикают live — see выше, ограничение задокументировано, не баг.
