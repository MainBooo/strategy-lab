# Адаптивный UI-аудит (Этап 5/6)

Автоматизированный прогон приложения через реальный Chromium (pip `playwright`,
установлен в `.venv`, отдельно от MCP-плагина Playwright) по всем ключевым
экранам на диапазоне разрешений — от узкого мобильного до широкого десктопа.
Скрипт: `scripts/playwright_ui_audit.py`.

## Как запустить

```bash
cd /opt/moex-strategy-lab-v3
.venv/bin/python scripts/playwright_ui_audit.py            # все 9 разрешений
.venv/bin/python scripts/playwright_ui_audit.py mobile      # фильтр по имени viewport
```

Ходит через nginx-прокси `http://127.0.0.1:8061/` — **не** напрямую на 5060:
Chromium сам блокирует этот порт как `net::ERR_UNSAFE_PORT`.

Результат: `test-results/ui-audit/<viewport>/*.png` (скриншоты каждого
сценария) + `test-results/ui-audit/report.json` (машиночитаемый список
находок). Каталог `test-results/` в `.gitignore` — это локальный артефакт
прогона, не часть репозитория.

## Сценарии (15 на каждое разрешение)

Главная → Хранилище данных (открыть/закрыть) → Бэктест (автозапуск) → История
бэктестов → Карточка результата (открыть/закрыть) → Анализ графиков (один
график) → Анализ графиков (мультиграфики/сетка) → Fullscreen графика
(войти/выйти) → Market Replay → Портфель → Таблица сделок → Модалки/формы.

## Автоматические проверки на каждом шаге

- Горизонтальный overflow (`document.documentElement.scrollWidth` >
  ширины viewport).
- Ошибки консоли браузера (`console.error`) и необработанные JS-исключения
  (`pageerror`).
- HTTP 5xx на любой сетевой запрос страницы.

## Результат прогона от 2026-08-04

**135/135 проверок чистые** (9 разрешений × 15 сценариев) — `report.json`:
ни одного `issues` ни на одном шаге. Выборочно сверено визуально
(скриншоты `mobile-360x800` — самое узкое разрешение — для сценариев
графиков, Market Replay и модалки формы заказа стратегии): вёрстка
корректна, ничего не обрезано непреднамеренно, лента котировок в шапке —
горизонтально скроллящийся виджет с намеренным overflow (не баг).

## Известные false positives предыдущих прогонов (не баги приложения)

Зафиксировано при отладке самого скрипта аудита, не приложения:

1. **Выход из fullscreen через `Escape` не срабатывает в headless Chromium**
   — `requestFullscreen()` резолвится без реального OS-уровневого fullscreen
   в headless-режиме. Скрипт использует клик по кнопке `#caFullscreenBtn`
   вместо `Escape`.
2. **`page.click()` по `#openMarketDataManager` ловил `Timeout 30000ms
   exceeded`** — модалка `.mdm-open` реально открывается с первого клика, но
   Playwright's post-click stability-check видит, что цель тут же перекрыла
   открывшаяся модалка, и бесконечно ретраит клик несмотря на то что
   результат уже достигнут. Исправлено на `page.evaluate(() => el.click())`
   (сырой DOM-клик, минует stability-check).

## Реальный баг, найденный и исправленный в процессе Этапа 3/5

CSS grid `1fr` без `minmax(0,1fr)` в мобильном `@media` ломал ширину (canvas
графика распирал контейнер) — найден и исправлен ещё в Этапе 3, не повторялся
в последующих прогонах.

## Сопутствующий a11y-фикс (найден при подготовке этого аудита)

`#marketDataManagerRoot.mdm-open` был `display:block`. Оба прямых ребёнка
(`.mdm-backdrop`, `.mdm-modal`) — `position:fixed` и не нуждаются в этой
обёртке для layout; как `block`-бокс без in-flow контента она схлопывалась в
нулевую высоту. Визуально незаметно (fixed-дети красятся и ловят клики вне
зависимости от бокса предка), но ломало собственный bounding rect элемента
для screen reader'ов и автоматизации. Исправлено на `display:contents`
(`static/styles.css`).
